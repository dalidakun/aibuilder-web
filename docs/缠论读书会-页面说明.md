## 正文注释（跨用户，按段落聚合）

在阅读页选中任意文字即可写注释，**不需要登录**：

- 选中文字 → 浮出「✎ 注释」→ 写注释；**署名自动取头像菜单 →「我的名字」**（没设置就用账户名，
  再没有就是「匿名读者」），弹层里只读，不能直接改
- 注释按课存在云数据库 `chanAnnotations`，用 `lessonNo`（1–108）区分，
  **一课一份，互不混淆**
- **注释按段落聚合**：某一段里有注释，这一段末尾就浮出一个小按钮「注 N」，
  一个段落只有一个入口，段内所有读者的注释都在这一处
  - 点按钮 → 右侧展开这一段所有注释，**再次点同一个按钮收起**
  - 浮层从顶部菜单下沿一直伸到屏幕底部：桌面右侧 380px、手机整屏；
    内嵌 iframe 时顶部菜单在 iframe 外面，浮层就从 iframe 顶边开始
  - 标题 / 小标题上写的注释，入口就显示在标题末尾，不会掉到第一段
  - 点另一段的按钮直接切到那一段；点浮层外面、按 Esc 也能收起
  - 右上角「↻」强制刷新；浮层里不显示段落开头的原文
- 浮层里每条：**上面是选中的原文，下面是注释内容**，带署名、时间、「定位」和（自己的）「编辑」「删除」；
  编辑只改注释内容和署名，原文锚点不动，保存后带一个「已编辑」小标
- 写 / 编辑注释的弹层可以按住标题栏拖动（限制在屏幕内）；只能点右上角「×」（或「取消」/ Esc）关闭，
  **点弹层外面不会关**，避免写到一半误点丢失
- 弹层底部「署名」显示 `我的名字`（不带 @），只读；要改名字去右上角头像菜单 →「我的名字」。
  自己的旧注释也会用当前名字显示；改名后服务端会把本人历史注释 / 提问 / 回复的署名一起改掉
- 只有自己写的注释才有「编辑」「删除」，别人的注释只能看和定位
- **画线只画自己的**：正文里的浅绿色标记只标出本浏览器自己写的注释，别人的注释不铺在正文上；
  但段落入口的「注 N」、浮层里的列表和计数始终是**全量**（本课所有读者）
- 自己写过的文字点标记 → 展开所在段落的浮层并把这条滚进视野；
  别人的注释点浮层里的「定位」→ 滚到它所在的那一段，并让段落入口闪一下
- 原文改动后定位不到的旧注释不会丢：统一挂到正文末尾的「更早的注释」里，
  浮层标题也显示「更早的注释」
- 段落入口按钮**不放文本节点**（计数用 CSS `::after` 画），所以加按钮不会改变
  正文的「文本流偏移」，注释锚点始终稳定
- 匿名身份是浏览器本地生成的 `clientId + secret`（localStorage `chan:anno:*`）；
  删除由服务端用 `clientHash` 校验，只能删自己写的那条
- 接口（`cloudfunctions/api/index.js`）：`getChanAnnotations` / `createChanAnnotation` /
  `updateChanAnnotation` / `deleteChanAnnotation`。匿名可读、可写；读接口按课返回
  （默认 300 条，最多 500 条）；同浏览器 10 分钟最多发 20 条（轻量频控）。
  编辑和删除一样要校验 `clientId + clientHash`，只能改自己那条
- 锚点存「课内文本流偏移」`anchor:{s,e}`，换设备、换字号都能定位；原文若改动，
  客户端会退回用 `quote` 在课文里重新查找
- 前端在 `site/assets/js/chan-annotations.js`，样式在 `site/assets/chan.css`
- **省成本**：每课注释在浏览器本地缓存 5 分钟（`localStorage` 的
  `chan:anno:cache:<lessonNo>`，最多保留 20 课）。刷新页面、切回本课、打开浮层
  都不会重复请求云端；点浮层右上角「↻」才强制刷新；发布/编辑/删除后同步更新本课缓存。
  缓存按 `lessonNo` 分开存，**课与课互不混淆**

## 每课提问（可附图）

- 每篇文章末尾一块「提问」区（原「评论」），按 `lessonNo` 归属，**课与课互不混淆**
- 每条提问/回复左侧显示用户**自己上传的头像**（读账号资料里的头像 `tradeAvatarGet`，
  存到 `chanProfiles` 按 clientId 关联）；没上传过就显示绿色首字默认头像
- 提问框只有输入框、「添加图片」和「发布提问」，不单独要求填用户名；
  署名自动取头像菜单 →「我的名字」，没设置就用账户名，再没有就是「匿名读者」，列表直接显示姓名（不带 @）
- **提问和回复都可以附图**，最多 3 张，也可以只发图片、不写字：
  - 图片在浏览器里先压：长边 1600px、铺白底、JPEG 0.78 起，优先保清晰度，按体积继续降质量；
    单张压到约 22 万字符以内、合计约 66 万字符以内才上传
  - 选完图先在输入框里显示 64px 缩略图，可逐张删除；列表里只显示 88px 缩略图，
    点缩略图放大后可以用左右按钮 / ← → / 手机左右滑动查看同一组里的其它图片
  - 服务端再兜底：最多 3 张、单张 ≤24 万字符、合计 ≤70 万字符，
    只接受 `data:image/(jpeg|png|webp);base64,` 前缀
  - `getChanComments` 单次返回的图片总预算 2MB 字符；超额时较早的提问只回文字，
    带 `imagesHidden`，前端显示「图片已省略（较早的提问）」，避免一次读拖回几十 MB
- 任何用户都能提问、回复；楼中楼只做一层，回复的回复也挂到主楼
- **只有管理员能删除/置顶**：普通用户每条提问只看到「回复」按钮；管理员可删除任意提问、置顶/取消置顶主楼
- **删除后彻底不显示**：`getChanComments` 不再返回已删除提问，主楼删掉时它下面的回复一并消失，页面不出现「该提问已删除」占位
- 匿名身份与正文注释共用 `clientId + secret`；管理员存在 `chanAdmins`，
  记录 `clientId + clientHash`（sha256(clientId + "\n" + secret)）
- **randeng 已是管理员**：绑定的是写注释那个浏览器的身份
  `1fca961f4ebadce4b54554af`。在同一个浏览器打开读书会，提问区会显示「管理员」徽标；
  换设备需要再往 `chanAdmins` 插一条新的 clientId/clientHash
- 接口（`cloudfunctions/api/index.js`）：`getChanComments` / `createChanComment`
  （新增可选 `images` 数组） / `deleteChanComment` / `pinChanComment` / `saveChanAvatar`；
  改名用 `updateChanDisplayName`（按 `clientId` 批量改本人历史注释 / 提问 / 回复的署名）
- 集合：`chanComments`（一条提问一个文档，`parentId` 为空是主楼，`images` 存压缩后的 data URL）、
  `chanAdmins`、`chanProfiles`（`_id` = clientId，存用户头像 data URL）
- 前端在 `site/assets/js/chan-comments.js`；每课提问本地缓存 60 秒，右上角「↻」立即刷新
- 提问区在正文之外，选中提问文字不会触发正文注释；正文注释的锚点也会跳过提问区

`tcb fn code update` 不会动云函数的环境变量，别用 `tcb fn deploy`（会按本地配置覆盖）。

## 内容从哪来

现在正文源是 MOBI 电子书 `C:\Users\Administrator\Desktop\缠中说禅.mobi`
（非 DRM、MOBI6、UTF-8）。`tools/extract_chan_mobi.py` 解包后按
「教你炒股票N」的章节锚点抽成 JSON：

- 章节：108 篇，按课号 1–108 一一对应；**标题以书里为准**，不按标题匹配
- 正文：段落按原顺序；每篇后面的编者附文「缠论点睛 / 投资微言 / 注释（脚注）」**整段丢弃**，页面上只留原文
- 日期：优先取标题里的日期，没有就从正文「时间：…」补
- 插图：书里正文中的 205 张插图按位置落进正文，长边压到 860px 存 WebP，图注沿用书里的「图1-1 …」
- 依赖：`pip install mobi beautifulsoup4 lxml pillow`

重新生成：

```bash
python tools/extract_chan_mobi.py
python tools/build_site.py --sync
```

旧的 Word 抽取器 `tools/extract_chan.py`（`E:\教你炒股票系列.docx`）还留着作备用来源，
产物 JSON 结构相同，换回 Word 版重跑即可。Word 版有两个坑：

1. **字被存成图片**：Word 字体子集里缺「早」这类字，导出后变成一张 38×39 的位图。
   脚本按尺寸识别出来，再用同一份文字的 PDF 版（`缠中说禅文集--教你炒股票系列.pdf`）
   对上下文，把字补回文本。
2. **U+F8FF 占位符**：同类缺字还会留下私有区字符 `U+F8FF`，同样的方式对着 PDF 补字；
   对不上就当换行残留丢掉。

## 重新生成

原文有改动时（脚本默认读 `E:\教你炒股票系列.docx`）：

```bash
# 1) 先把 PDF 转成纯文本，供缺字对照（只需一次，pypdf 装在系统 Python 里）
python -c "from pypdf import PdfReader; import pathlib; \
r=PdfReader(r'E:\0-知识库\技术交易\缠中说禅文集--教你炒股票系列.pdf'); \
pathlib.Path('.tmp/chan_pdf.txt').write_text('\n'.join(p.extract_text() or '' for p in r.pages), encoding='utf-8')"

# 2) 抽正文 + 插图（需要 python-docx、Pillow）
python tools/extract_chan.py --pdf-text .tmp/chan_pdf.txt

# 3) 重建整站（dist/chan/index.html 由 build_site.py 现场拼出来）
python tools/build_site.py --sync
```

`build_site.py` 会把 `site/data/chan-lessons.json` 渲染进 `chan.template.html`，
和其余页面一样接受 `{{REL}}`、`{{ASSET_VER}}` 等占位符替换。

## 页面行为

- 全站是**一条顶部横向菜单 + 三条横向轨道**：交易练习 / 缠中说禅 / 大正藏经，

  高度 44px（手机 40px），当前项浅底加粗

  菜单里新增「我的名字」：输入中文名字后，注释 / 提问 / 回复的署名都用它，

- `#l0xx`：直接打开第 xx 课，复制地址即可分享
- 目录搜索：**只搜课程标题**，命中的行当场筛出来

- 翻课：顶部 `↑` `↓` 按钮、键盘 ← →

- 读到第几课也记在 localStorage（`chan:last`），下次打开直接续上
- 顶部工具条课次旁边有一句「选中文字即可注释」，窄屏自动隐藏
- 注释浮层从顶部菜单下沿一直伸到屏幕底部（iframe 里从 iframe 顶边开始），

## 交易复盘页（`/review/`）

**入口**：交易练习页右上角、贴着右侧边缘竖着的绿色「交易复盘」开关（`#btnReview` +
`#reviewOverlay`）。点一下整屏展开、再点收起，展开时从最右侧边缘一直铺到左侧边缘、
连顶栏和走势一起盖住；`trade.js` 在展开时给 iframe 发 `review:refresh` 让它重读账户
（刚平完仓不用手动刷新），收起时发 `review:save` 先把没保存的正文存下来。
iframe 内按 Esc 也会把浮层收起。

照 zentrader（`E:\3-zentrader`）那个 exe 的「交易复盘」界面做的三栏：

- 左：**历史记录**——「交易练习」账户里的平仓记录（本机 `huideng.trade.guest`，
  登录过就读云端快照 `huideng.trade.cache`），按时间倒序。第一行是「多/空 + 盈亏绝对值
  + 收益率」，多单红、空单绿，最右是这一笔的百分比；第二行是持仓时间和平仓时间。
  右上角「导出」导出**全部**记录（含每笔的复盘文字）为 txt。
  这一栏桌面 240px（原来 286px，收窄后把宽度让给中间的复盘框），≤1100px 时 224px
- 中：**交易复盘**——选中一笔后，顶部信息条：初始余额 / 开仓时间 / 平仓时间 /
  复盘时间（第二行第一格，显示这篇复盘最后一次保存的时间，未保存为 `--`）/
  开仓价位 / 平仓价位；下面是复盘正文
- 右：**阶段统计**——上面是资金收益变动曲线，横轴是时间、纵轴是余额（刻度写在这一栏左侧，
  和下面指标格的左边界对齐），每个交易点一个小圆点，可在「阶段图 / 全周期图」之间切换；
  下面是紧凑的三列指标：
  起始日期、初始本金、期末余额、持续天数、阶段收益率、胜率、盈亏比、最大回撤、
  期望值、平均收益率、平均亏损率、年化拟合、月化拟合、交易笔数

**复盘正文的保存与图片**（和交易笔记同一套习惯）：

- **一分钟自动保存一次**（`AUTOSAVE_MS = 60000`，打字时不会重置计时），
  保存后顶部显示「已保存」；切到别的记录、按 **Ctrl+S** 也会立刻保存
- 直接 **Ctrl+V 粘贴截图**：先压到长边 1280px、JPEG 质量 0.72，
  超过 180KB 继续降质量，以 data URL 存进 `huideng.trade.reviews` 的 HTML 里，
  刷新不会丢（之前只存纯文本，图片自然就没了）
- 正文里的图片点一下看大图（浮层，点一下或 Esc 关闭）
- 历史记录右上角两个按钮：**刷新**（重新读一次账户和重置记录，平仓、重置完不用重开页面）
  和 **导出 PDF**（全部平仓记录 + 各自复盘，走浏览器打印，选「另存为 PDF」即可）
- 导出文件名默认是「用户名-交易复盘-年份」；记录跨年时按钮旁边会出现年份下拉
  （只有一年就不显示），只导出所选年份那一段
- 历史记录的每一条是浅色块，选中后颜色更深，一眼能看出当前在看哪笔

**阶段怎么分**：以「重置资金」为分界——每重置一次资金就开一个新阶段，
`trade.js` 重置成功时往 `huideng.trade.resets` 记一条 `{at, amount}`，
复盘页按这条记录把平仓记录切段，每段的初始本金就是那次重置的金额。
重置金额最低 100（前端 `RESET_MIN`、云端 `tradeReset` 都是 100，默认仍是 10 万）。

**重置资金怎么显示**：

- 历史记录里插一条浅色分隔行「重置资金 50,000.00 2026-11-14 13:08」，
  标明从这里进入新阶段；它不是交易记录，不可点击，也不参与盈亏统计
- 「全周期图」在重置那一刻画一条竖虚线并标「重置」，曲线在这里跳一次
  （资金从旧阶段余额跳成重置后的金额）
- 「阶段图」从该阶段本金起画，只留一条虚线基准，不写文字

**收益率口径**：单笔收益率 = 这笔盈亏 ÷ 这笔之前的余额；阶段收益率 =
（阶段期末余额 − 阶段初始本金）÷ 阶段初始本金。
